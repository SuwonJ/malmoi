# 더 나은 역방향 사전 검색 방법

이 문서는 방법론 조사와 실제 추가 실험 결과를 연결하는 진입점입니다. 현재 실험의 실행 상태와 결과는 [LATEST.md](LATEST.md)에서 확인합니다.

## 추가 실행: KURE와 Qwen3 후보 재평가

동일한 4개 개발 질의에 대해 문자/E5 각각 상위 200개 단어의 뜻풀이 합집합을 고정했습니다. 문항당 358–377개 뜻풀이이며, 정답을 후보에 강제 삽입하지 않았습니다. 전체 사전 dense 검색이 아니라 **후보 생성 후 임베딩으로 재평가하는 파이프라인**입니다.

| 방법 | nDCG@10 | Hit@1 | Hit@5 | Hit@10 |
|---|---:|---:|---:|---:|
| 기존 문자 전체 검색 기준선 | 0.4050 | 0% | 0% | 25% |
| KURE-v1 int8 CLS 후보 재평가 | **0.6197** | 25% | **75%** | **100%** |
| Qwen3-Embedding-0.6B int8, 작업 지시 포함 | 0.1532 | 0% | 0% | 25% |
| Qwen3-Embedding-0.6B int8, 작업 지시 제외 | 0.2895 | 25% | 50% | 50% |

현재 우선 검증 후보는 **문자·E5 후보 생성 → KURE 후보 재평가**입니다. `먼지잼`은 1위, `서성거리다`는 2위, `어슴푸레하다`는 3위에 나타났습니다. 전체 문항 결과는 [KURE 실행 보고서](runs/20261016T153031.806345Z-kure-screen/REPORT.md)에서 확인합니다.

KURE는 변환본 README의 평균 풀링 권고 대신 [원본의 CLS 풀링 설정](https://huggingface.co/nlpai-lab/KURE-v1/blob/8b418a58414668e75532ed045c22d9ca018ae2b2/1_Pooling/config.json)을 적용했습니다. Qwen은 마지막 유효 토큰 풀링과 영어 작업 지시를 사용하고 지시를 뺀 대조군도 시험했습니다. 둘 다 공개 int8 변환본이며 float 원본 대비 정합 검증을 수행한 결과는 아닙니다.

KURE 질의 처리 p95는 문서 벡터가 이미 있다는 조건에서 20.7ms였습니다. 이 값은 앞단 검색·모델 로드·문서 캐시 미스 처리를 제외합니다. 후보용 1,237개 고유 뜻풀이의 벡터 생성은 26.5초가 걸렸습니다. 임의의 신규 질의를 지원하려면 전체 사전 KURE 벡터를 미리 만들거나 캐시 미스 때 추가 비용을 지불해야 합니다. 전체 중복 제거 뜻풀이 169,950개를 1024차원 float32로 저장하면 벡터만 약 664MiB가 필요하며 모델·E5·문자 인덱스·런타임은 별도입니다.

**다음 검증:** 문항/후보 라벨을 늘린 뒤 KURE 전체 사전 벡터를 생성해 후보 생성 의존성을 비교하고, 실제 기기에서 모델 로드·전체 RAM·질의 p95를 측정합니다. 4문항에서 얻은 100% Hit@10을 일반화 성능으로 해석하지 않습니다. 추가 후보도 [블라인드 판정 파일](quality_review.csv)에 합쳤습니다.

## 이전 실행: E5·BGE 실험의 결론

[전체 14개 설정 비교표](QUALITY.md) · [문항별 검색 결과와 로그](runs/20261015T062710.638809Z-advanced/REPORT.md) · [교차 인코더 결과](runs/20261015T064333.730686Z-rerank/REPORT.md)

현재 결과는 **한 방법이 모든 지표에서 우월하지 않습니다.** 정확한 목표 단어를 10개 안에 포함시키는 목적이라면 E5+문자 결합이 다음 검증 후보이고, 현재 등급 라벨에 대한 nDCG는 문자 TF-IDF가 가장 높았습니다.

| 방법 | nDCG@10 | Hit@10 | Hit@100 | 호스트 시간 |
|---|---:|---:|---:|---:|
| 문자 TF-IDF | 0.4050 | 25% | 75% | p95 13.3 ms 실측 |
| E5-small 단독 | 0.2081 | 25% | 75% | p95 41.7 ms 실측 |
| E5 + 문자 RRF | 0.3637 | 50% | 100% | 단계 합산 88.0 ms |
| E5 + 문자 → BGE, 표제어+뜻풀이 100개 | 0.2722 | 50% | 후보 Hit 100% | 단계 합산 3815.0 ms |

- **실제 이득:** 문자만으로 55위였던 `먼지잼`이 E5에서는 1위입니다. 결합 검색은 `먼지잼` 7위, `아슴푸레하다` 8위로, 정답을 상위 10개에 넣는 문항이 1개에서 2개로 늘었습니다.
- **남은 실패:** 결합해도 `서성거리다`는 21위, `미적거리다`는 55위입니다. 따라서 개선을 전체 해결로 볼 수 없습니다.
- **투자 우선순위:** 지금은 BGE 재순위화보다 E5+문자 결합을 유지하고, 한국어 특화/작업 지시형 임베딩과 실제 질의의 판정 데이터를 추가하는 쪽이 유망합니다. BGE는 비용 증가 대비 현재 라벨 지표의 이득이 없었습니다.
- **평가 한계의 실제 사례:** 재순위화에서 `미룸미룸`(일을 자꾸 미루어 시간을 끌어 가는 모양), `우련히`(형태가 약간 나타나 보일 정도로 희미하게)가 나왔으나 현재 라벨에는 없습니다. 질의와 맞아 보이는 후보일 뿐, 사람이 검토하기 전에는 정답으로 추가하거나 재순위화가 더 좋다고 판정하지 않습니다.
- **후속 무거운 후보:** KURE-v1 또는 Qwen3-Embedding-0.6B를 같은 전체 사전/판정셋으로 비교하는 실험을 우선 제안합니다. 이전 실행에서는 두 모델을 실행하지 않았으며, 위 추가 실행에서 후보 재평가를 완료했습니다.
- **실험 규모:** 4문항 개발셋에서 여러 설정을 비교했습니다. 이 수치로 일반화나 통계적 유의성을 주장하지 않습니다. 저장된 `quality_review.csv`는 0–3 등급을 사람이 입력할 수 있도록 비워 두었습니다.

BGE 단독 순위가 불안정한 원인을 보기 위해 검색 순위와 BGE 순위를 절반씩 결합한 후속 진단 2개도 수행했습니다. 최고 nDCG는 0.3361로 문자 기준선을 넘지 못했습니다. 이는 결과를 본 뒤 추가한 개발셋 탐색이며 별도 검증 성능이 아닙니다.

## 우선 시험할 구조

**문자/형태소 검색 + 의미 임베딩 검색 → 후보 결합 → 상위 후보 교차 인코더 재순위화**를 비교합니다. 비용이 큰 문서 임베딩은 사전이 바뀔 때 미리 계산하고, 온라인에서는 질의 한 개를 임베딩하거나 후보 50–100개만 정밀 평가합니다.

각 단계는 다른 문제를 다룹니다.

| 방법 | 해결하려는 문제 | 비용이 늘어나는 위치 | 이번 범위 |
|---|---|---|---|
| Kiwi 형태소 TF-IDF/BM25 | 조사·활용형 때문에 같은 의미의 어휘가 불일치 | 오프라인 형태소 분석 + 질의 분석 | 전체 고유어 사전 실험 |
| multilingual-E5-small int8 | 설명과 뜻풀이의 어휘가 달라도 의미가 가까움 | 문서 임베딩 사전 계산, 질의 임베딩 | 전체 고유어 사전 실험 |
| RRF 결합 | 의미 검색과 문자 검색이 놓치는 후보가 다름 | 검색 2회 + 순위 합산 | 문자/E5/형태소 조합 실험 |
| BGE-reranker-v2-m3 int8 | 후보는 있지만 상위 순위가 잘못됨 | 질의–뜻풀이 쌍당 교차 인코더 추론 | 상위 50·100개 실험 |
| KURE-v1 / KoE5 | 더 강한 한국어 검색 표현 | 더 큰 임베딩 모델/벡터 | KURE 후보 재평가 실행; KoE5 미실행 |
| 사전 도메인 대조학습 + 어려운 오답 | 일반 문서 검색과 역방향 사전의 목적 차이 | 학습 데이터 구성/학습 | 후속 실험 제안 |

### 1. 한국어 형태소 검색

Kiwi의 형태소·품사 분석으로 조사와 어미를 분리하고 명사·동사·형용사·부사·보조용언을 검색 특징으로 사용합니다. 부정 표현을 보존하려고 보조용언을 포함했습니다. 이번 구현은 내용 형태소 1–2그램, min_df=1, 최대 20만 특징입니다. 단순히 조사만 제거하면 품질이 좋아질 것이라고 가정하지 않고 문자 기준선과 비교합니다. [Kiwi 개발자 문서](https://github.com/bab2min/kiwipiepy)

### 2. 전체 의미 검색

E5는 질의와 문서를 각각 벡터로 바꾸는 bi-encoder입니다. 모델이 학습된 방식에 맞춰 한국어에도 `query: `, `passage: ` 접두어를 넣고 attention mask를 적용한 평균 풀링 후 정규화합니다. 이번 실험은 384차원 E5-small의 ONNX int8 변환본입니다. 원본 float 모델의 성능과 동일하다고 가정하지 않습니다. [원본 E5 모델 설명](https://huggingface.co/intfloat/multilingual-e5-small), [ONNX 변환본](https://huggingface.co/Xenova/multilingual-e5-small)

전체 266,506개 뜻풀이 중 정확히 같은 문장은 묶어 169,950개만 임베딩합니다. 같은 뜻풀이의 표제어는 모두 검색 결과 후보로 남습니다. 최대 128토큰에서 잘리는 뜻풀이는 517개(0.304%)이며, 중앙값은 19토큰, 95백분위는 59토큰입니다([길이 감사](e5_length_audit.json)). 벡터 크기는 약 249 MiB이며 표제어→벡터 매핑과 모델 가중치, 어휘, 문자열 비용은 별도입니다. 인덱싱은 청크 단위로 진행 상태를 저장해 재실행 시 이어갑니다.

이번에는 실제 전체 의미 검색을 수행하므로 문자 후보에 없는 정답도 찾을 수 있습니다. 정답을 후보 목록에 넣거나 평가 라벨을 임베딩 입력에 사용하는 방식은 쓰지 않습니다.

### 3. 순위 결합

문자 TF-IDF, BM25, 임베딩 cosine 점수는 범위가 다릅니다. RRF는 각 방법의 순위에 `1/(60+rank)`를 부여해 합합니다. 이번에는 방법별 상위 1000개 뜻풀이만 결합하고 최종적으로 같은 단어의 최고 뜻풀이를 사용합니다. 결합이 항상 개선을 보장하지는 않으므로 의미 단독과 함께 보고합니다. [RRF 원 논문](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)

### 4. 검색 후 교차 인코더 재순위화

Bi-encoder와 달리 교차 인코더는 질의와 후보 뜻풀이를 한 쌍으로 입력받아 관련성 점수를 계산합니다. 전체 사전의 모든 쌍을 온라인 처리하기에는 비싸므로, 먼저 검색한 상위 후보에만 적용합니다. 후보에 없는 정답을 복구할 수 없으므로 후보 Hit와 최종 Hit를 함께 봅니다. [Sentence Transformers의 retrieve-and-rerank 설명](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

이번 후보 모델은 다국어 BGE-reranker-v2-m3입니다. 기본 bge-reranker-base/large의 중국어·영어 용도와 혼동하지 않도록 v2-m3를 선택했습니다. 원본 모델은 BAAI, 실행 파일은 onnx-community의 양자화 변환본이며 revision과 파일 해시를 기록합니다. [BAAI 모델 설명](https://huggingface.co/BAAI/bge-reranker-v2-m3), [ONNX 변환본](https://huggingface.co/onnx-community/bge-reranker-v2-m3-ONNX)

`뜻풀이만`과 `표제어: 뜻풀이` 입력을 비교합니다. 후자는 사용자가 단어의 일부를 기억하는 질의에도 유용할 수 있다는 가설이며, 이점은 실험으로 확인해야 합니다.

### 5. 더 무거운 한국어 특화 임베딩

KURE-v1은 BGE-M3를 한국어 데이터로 학습한 1024차원 모델이며, KoE5는 multilingual-e5-large를 한국어 triplet 데이터로 학습한 모델입니다. 개발팀의 한국어 검색 벤치마크를 참고할 수 있으나, 여기서 필요한 희귀어·의태어·역방향 사전 검색의 우열을 보장하지는 않습니다. small 모델의 개선 폭을 본 뒤 같은 평가로 교체 비교할 후보입니다. [KURE-v1](https://huggingface.co/nlpai-lab/KURE-v1), [KoE5](https://huggingface.co/nlpai-lab/KoE5)

BGE-M3 자체는 dense·sparse·multi-vector 검색을 지원합니다. 특히 token 단위 상호작용을 쓰는 multi-vector 방식은 후속 후보지만, 단일 벡터보다 저장/연산 비용이 커지므로 현재 단계에서는 단일 의미 벡터와 후보 재순위화를 먼저 검증합니다. [BGE-M3 개발팀 문서](https://bge-model.com/bge/bge_m3.html)

최근 소형 후보로는 **Qwen3-Embedding-0.6B / Qwen3-Reranker-0.6B**도 비교할 가치가 있습니다. 질의에 작업 지시를 넣을 수 있어 “설명에 해당하는 한국어 단어의 뜻풀이 검색”처럼 목적을 명시하는 실험이 가능합니다. 임베딩은 32–1024차원 출력을 지원하므로 품질과 인덱스 크기를 함께 비교할 수 있습니다. 다만 0.6B 모델의 질의 추론 비용이 E5-small보다 클 수 있으며 Qwen3-Embedding은 위 후보 재평가에서 시험했고 Qwen3-Reranker는 아직 시험하지 않았습니다. [Qwen 임베딩 모델 설명](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B), [Qwen 재순위화 모델 설명](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)

**EmbeddingGemma**는 온디바이스 배포를 염두에 둔 별도 다국어 임베딩 후보입니다. 이번 결과보다 우수하다고 단정하지 않고, 실제 기기 제약을 다시 적용하는 단계에서 한국어 역방향 사전 평가에 포함할 수 있습니다. [Google 공식 문서](https://ai.google.dev/gemma/docs/embeddinggemma)

### 6. 도메인 학습과 증류

일반 검색 모델의 한계가 남으면 질의 설명–정답 뜻풀이 쌍으로 대조학습을 진행합니다. 문자/의미 검색에서 나온 혼동되는 다른 단어를 어려운 오답 후보로 삼되, 실제 유의어를 오답으로 학습하지 않도록 사람이 판정합니다. 사전의 뜻풀이를 그대로 복사한 질의를 학습·평가 양쪽에 쓰면 쉬운 문자열 매칭을 평가하게 되므로 실제 사용자식 바꿔 말하기가 필요합니다.

역방향 사전과 정의 생성의 공동 학습도 연구돼 있습니다. 다만 다른 언어/데이터의 개선을 이 사전에 그대로 적용할 수는 없습니다. [역방향 사전·정의 모델링 공동 학습 연구](https://arxiv.org/abs/2205.04602), [검색 인덱스에서 어려운 오답을 구하는 ANCE 연구](https://arxiv.org/abs/2007.00808)

큰 모델이 분명한 품질 개선을 보이면 오프라인 teacher로 사용하고 작은 질의 인코더로 증류하는 것이 장기적인 모바일 방향입니다. 먼저 품질 상한을 확인한 다음 경량화를 하는 순서입니다.

## 실험 판단 원칙

- Hit@100이 낮으면 후보 생성 개선(임베딩/인덱싱 방식)이 우선입니다.
- Hit@100은 높고 Hit@10이 낮으면 재순위화에 연산을 쓰는 것이 타당합니다.
- 무거운 방법이 개선되지 않으면 복잡성을 늘리지 않고 원인을 문항별로 확인합니다.
- 4개 개발 문항에서의 최고 수치를 최종 성능으로 주장하지 않습니다. 후보 판정 풀을 늘리고 사용자 질의를 추가해 검증합니다.
- 모바일 5초 예산은 질의 전체 지연, 초기 로드, 최대 메모리로 검증합니다. 오프라인 인덱싱 시간과 온라인 질의 시간을 분리합니다.
- 합성 질의는 학습 보조로 사용할 수 있지만, 생성 모델이 정한 라벨만으로 독립 평가를 대체하지 않습니다.
